Embed with an iframe

Three ways to show the same tag #100. This host page imports no JavaScript or player CSS. Each frame owns its drawing and, when needed, its controls.

Full player with controls

Play, pause, scrub and change the ink. This example includes the optional controls and a remove button that releases the player.

Open the player on its own

<iframe src="./player.html"
  title="Graffiti player"
  loading="lazy"
  style="width:100%;height:1120px;border:0">
</iframe>

Animation only

The drawing fills its frame and loops without controls. No UI module or stylesheet is loaded. With reduced motion enabled, it shows the finished tag instead.

Open the animation on its own

<iframe src="./playback.html"
  title="Animated graffiti drawing"
  loading="lazy"
  style="width:100%;aspect-ratio:1;border:0">
</iframe>

Finished drawing

Put a frame on another site

Each example uses bundled JSON. Its JSON and module URLs resolve relative to the framed page, not the host page.

  • Replace src with the absolute HTTPS URL of your hosted example. Serve the modules and tag.json alongside it over HTTP or HTTPS, not file://.
  • Set the frame size on the host page. The drawing fits its stage, but the player does not resize the outer iframe. Leave enough height for controls or introductory text.
  • The host's frame-src policy must allow the player URL. The player's frame-ancestors and X-Frame-Options headers must allow the host.
  • If you add a sandbox, module loading and playback need allow-scripts allow-same-origin. Use those permissions only for content you trust.
  • The host cannot control a cross-origin player through these examples. There is no postMessage API.

You can also embed the full demo with ../?renderer=canvas&id=147&fullscreen=1 as the source. That version loads its tag from 000000book rather than the bundled JSON.
